## Context
The word bank is still shaped like a German bank: the field is `example_de` (and `exampleDe` in TypeScript), the AI answer uses a `"de"` key, the TSV/JSON/translation files sit in single, language-less folders, and the app and database names are `GermanBuddy`/`germanbuddy.db` literals. A Spanish bank cannot be added until a bank belongs to a language. After this task: neutral field names everywhere in code, one folder per language for sources and generated data, the scripts work per language, and exactly one language is active per build through three tiny generated seam files. **German behavior and the existing data on users' phones do not change.**

Plan: 041 done, 042 (this), 043 templated UI strings, 044–046 Spanish, 047 variants and build scripts, 048 store/legal, 049 QA.

### Implementation notes

**TSV column order is positional and does not change**; only the JSON key is renamed (`COLS` entry `example_de` → `example`). The existing TSVs need no edit besides moving.

**AI answer and cache.** Prompt: `{ "target": "a <Language> sentence using the word", "native": "…" }`. Parsing: `typeof (e.target ?? e.de) === 'string'`; the returned `InsightExample` always uses `target`. Cached payloads already stored in `ai_word_notes` have `de`: normalise on read in `vaultService` (and in the live parse) with one helper `normalizeExample(e: { target?: string; de?: string; native: string })` in `wordInsight.ts`, exported and unit-tested. Never rewrite the cache rows.

**Data-layer boundary.** SQL keeps `example_de` (column names are frozen). Row interfaces keep a field `example_de` internally if that is what the query returns, and the mapping to the domain object sets `example`. Do not add `ALTER`/migrations.

**Bank folders.** `index.ts` keeps the same public API (`WORD_BANK`, `allEntries`, `entryId`, `CEFR_ORDER`, types). Only the import source changes (`./active`). `WordBankEntry.example_de` → `example`.

**`language.json`** (German):
```json
{
  "code": "de",
  "ruleCodes": ["VERB_CONJ_REGULAR", "NOUN_GENDER", "WORD_ORDER_V2", "NEGATION_NICHT_KEIN", "VERB_CONJ_IRREGULAR", "ACCUSATIVE_MASC", "ACCUSATIVE_PREP", "SEPARABLE_VERB", "DATIV_PREP", "DATIV_INDIRECT_OBJ", "MODAL_VERB", "PERF_SEIN_HABEN", "SUBORD_VERB_FINAL", "KONJUNKTIV_II", "GENITIV_CASE", "PASSIVE_VOICE", "KONJUNKTIV_I", "EXTENDED_ATTR"],
  "partsOfSpeech": ["noun", "verb", "adj", "prep", "conj", "adv"],
  "articles": ["der", "die", "das"]
}
```
Validator rules that were German constants become: `grammar_angle ∈ ruleCodes`; `part_of_speech ∈ partsOfSpeech`; a noun's `article ∈ articles` and non-nouns have `article === null`; the topic list stays global (`topics.ts`, 8 keys, language-independent). Keep every other existing check (duplicates, required fields, IPA present, example contains the word, level counts…).

**Scripts per language.** Language folders are `scripts/wordbank/<code>/` where `language.json` exists. Resolve root with `--root <dir>` (default `scripts/wordbank`, used by tests with a temp fixture) and output root `--out <dir>` (default `src/data/wordbank`). The build refuses (non-zero exit, message) when a language folder lacks `language.json` or a level TSV. Translation output (`i18n/<native>.json`) is built **per language**; the set of native languages is whatever folders exist under `<lang>/i18n/`. The generated `wordContentLoaders.ts` covers only the **active** language (see below).

**`set-active-language.mjs <code>`** checks `scripts/wordbank/<code>/language.json` and `src/languages/<code>.ts` exist (clear error otherwise), then writes the three seams with a `// GENERATED by scripts/set-active-language.mjs — do not edit.` header:
- `src/data/wordbank/active.ts`: `import a1 from './<code>/A1.json'; … export const LEVEL_FILES = { A1: a1, … };`
- `src/i18n/wordContentLoaders.ts`: loaders for `src/data/wordbank/<code>/i18n/*.json` (same shape as today).
- `src/languages/active.ts`: `export { <code> as activePack } from './<code>';`
`build-wordbank` calls it for the active language (`BUDDY_LANG` env, default `de`) at the end, so a fresh clone is consistent. `npm run set:language -- <code>` runs it alone.

**App identity.** `backup.ts`: `const APP_TAG = getActivePack().app.backupTag` evaluated at use time (not import), `db.ts`: `openDatabaseAsync(getActivePack().app.dbFile, …)`. Keep the Italian text of the existing error strings (TASK-043 handles them).
